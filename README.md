## 系统架构

```
┌──────────────── VPS（7×24，UTC）────────────────┐
│  crypto_vps_update.py   每 4h  拉行情 → 合并去重    │
│  engine_vps.py          每 4h  算目标仓位（只算仓）  │
│  executor_vps.py        每 4h  下单执行（白名单）   │
│  shadow_vps.py          每日   影子账本对照         │
│  discipline_guard.py    每 2min 垃圾币强平 + 冷静期  │
│  health_patrol.py       每 30min 健康巡检 → 告警    │
│  daily_stats.py         每日   盈亏统计表           │
└───────────────────────────────────────────────┘
                     ▲
                     │ 单向同步（本地只读）
┌──────────────── 本地（人机界面）────────────────┐
│  DSH 智能体会话 / 钉钉遥控 / 看板 / 备份          │
└───────────────────────────────────────────────┘
```

**核心设计原则：能白嫖 Python 的绝不烧 token。**
日常运维全部是 VPS 上的纯 Python + cron（零 AI 成本）；只有需要判断力的事（策略迭代、异常排查）才动用智能体会话。

## 三个我认为最有价值的教训

### 1. 改名一个被 import 的模块 = 整条管道静默停摆 4 天

为了防止脚本覆盖数据，我把 `fetch_crypto_update.py` 改了名。结果 `crypto_vps_update.py` 的 `import` 直接崩，VPS 数据更新**静默停了 4 天**——没有报错弹窗，没有告警，只有影子账本在陈旧价格上一天天算着"信号"。

**修复**：抽出职责单一的 `okx_candles.py`；改任何被引用的模块前先 `grep` 引用，改完必须手动跑一次全管道。

### 2. 端口写死在代码里 = 升级即全链路断裂

新版把服务端口从 3080 迁到 19387，但：
- 消息机器人还在往 3080 发（消息全丢）
- 自愈任务还在监控 3080 → 误判"服务挂了" → **反复强杀新版进程**
- 监控哨兵还在报"3080 异常"

**修复**：让服务把真实端口写盘，所有组件读文件跟随；任何地方不写死端口。

### 3. 手写白名单 = 迟早误杀

我做了一个"垃圾币强平"的纪律锁，白名单是手写的短名单。结果它把用户的一笔**美股三倍做空 ETF（SOXS）**当成垃圾币强平了——当时那笔还浮盈。

**修复**：改成从交易所官方分类动态拉取（X 前缀 = 美股，其余 = 加密），**美股优先判定**；并且加了安全兜底——**分类不确定时只告警、绝不动手**。
