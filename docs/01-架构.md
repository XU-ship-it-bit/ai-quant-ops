# 系统架构

## 总览

```
VPS（7×24，UTC）                         本地（人机界面，按需开机）
├─ 数据层  crypto_vps_update.py 4h        ├─ DSH 智能体会话（判断/开发）
├─ 信号层  engine_vps.py        4h        ├─ 钉钉遥控通道
├─ 执行层  executor_vps.py      4h        ├─ 看板 / 盈亏统计查看
├─ 账本层  shadow_vps.py        每日      └─ 每日备份（04:30）
├─ 风控层  discipline_guard.py  2min
├─ 监控层  health_patrol.py     30min
└─ 记账层  daily_stats.py       每日
```

## 数据流

1. **行情**：交易所 REST → `data/crypto/{btc,eth,xrp,sol}_{1d,4h,1h}.csv`（全历史，增量合并去重）
2. **信号**：日线定方向（donchian / 均线交叉 + 200MA 过滤）→ 4H 择时（donchian 突破状态机）
3. **仓位**：标的级波动率目标 60%（clip 上限 3×）+ rebalance 阈值 0.10 + 组合总敞口上限 120%
4. **执行**：目标仓位 → 张数换算（合约面值）→ 白名单校验 → 市价单 → 落台账
5. **记账**：交易所账单 → 每日入账/亏损/手续费/净额 → 统计表

## 时间口径（最容易搞错的地方）

- 交易所日线以 **UTC 16:00** 为日界
- 影子和引擎在北京时间 16:20 / 每 4 小时整点后运行
- 盈亏统计按 **北京时间** 分日（UTC+8）
- **所有"今天"的判断必须显式指定时区**，否则跨日会错位

## 关键设计决策

| 决策 | 原因 |
|---|---|
| 日常运维用纯 Python + cron，不用 AI 智能体 | AI 会话按 token 计费，轮询是最贵的用法 |
| VPS 为唯一权威数据源，本地只读同步 | 避免双写冲突（曾因本地任务覆盖 VPS 数据导致账本失真） |
| 引擎与执行分离 | 引擎只算仓，执行层单独校验白名单和底仓 |
| 默认干跑（DRY_RUN） | 任何真实下单必须显式打开开关 |
| 端口/路径不写死 | 升级导致端口迁移，写死即全链路断裂 |
