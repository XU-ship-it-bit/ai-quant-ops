## 二、VPS 任务表（crontab）

| 时间（UTC） | 脚本 | 作用 |
|---|---|---|
| 每 4h :02 | `crypto_vps_update.py` | 拉 OKX 最近窗口 → 合并去重进全历史 CSV |
| 每 4h :06 | `engine_vps.py` | 冻结版 4H 仓位引擎（**只算仓不下单**）+ 翻转告警 |
| 每日 08:20 | `shadow_vps.py` | 影子三账本落盘（幂等，同日不重写） |
| 每 2 分钟 | `discipline_guard.py` | 垃圾币强平 + 冷静期（3/7/14 天递进） |
| 每 30 分钟 | `health_patrol.py` | 数据/引擎/影子/纪律锁健康 → 异常钉钉告警 |

**依赖库**：`okx_candles.py`（K 线拉取，纯只读）。
⚠️ 历史坑：改名/删除被其它脚本 import 的模块会导致整条管道静默停摆（09-27 数据断 4 天就是这么来的）。

## 三、时间口径（最容易搞错）

- OKX 日线以 **UTC 16:00** 为日界；`shadow_vps.py` 在 **08:20 UTC** 跑，取到的是**前一日**已收盘的日线。
- 本地 16:20 的旧影子任务**已下线**（会与 VPS 重复且本地数据不更新 → 出陈旧信号）。
- 本地 `USLedgerSync`（16:35 本地 = 08:35 UTC）从 VPS 拉账本，**VPS 版本优先**。

## 四、故障速查

| 症状 | 先查 | 处置 |
|---|---|---|
| 钉钉发消息没回 | ① `ding_bot.py` 在跑？② `team_data/.ding_bridge.port` 是否=19387？③ `curl -X POST 127.0.0.1:19387/dingin` 返回 ok？ | 重启 ding_bot（先删 `.ding_bot.lock`）；桥端口变了就更新端口文件 |
| DSH 反复被杀/起不来 | `netstat -ano \| findstr :19387`；自愈任务端口配置 | 自愈脚本端口必须是 **19387**（旧的 3080 会误判"DSH 挂了"→ 杀新版） |
| 数据不更新 | VPS `logs/crypto_update.log` 有无 ImportError | 修 import（库名 `okx_candles`）；手动跑一次补数据 |
| 影子账本不涨 | VPS `logs/shadow_vps.log`；cron 是否在 | 手动 `python shadow_vps.py`；同日幂等，需先删当天行才重写 |
| 仓位莫名被平 | `logs/discipline_guard.log` + `discipline_state.json` | 只应平**垃圾币**；美股（X 前缀 108 只）与 BTC/ETH/XRP/SOL 在白名单 |
| 守护进程成对出现 | 进程清单 | 已加 `singleton.py` PID 守卫；重复的杀掉较旧那个 |

## 六、纪律铁律（不可协商）

1. **不碰用户手动仓位**（只读检查；美股与 BTC/ETH/XRP/SOL 一律放行）。
2. **垃圾币 = 强平 + 冷静期**，冷静期**不可解锁**（3/7/14 天递进）。
3. **真金下单需用户签字**；引擎默认只算仓不下单。
4. **改任何口径 → 全菜单重跑 + 签字作废重签**。
5. **数字必须实测**，编造即作废。
